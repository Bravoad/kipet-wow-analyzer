# Warcraft Logs client and combat calculations

This adapter uses only the public client GraphQL endpoint at `https://www.warcraftlogs.com/api/v2/client` and server-side client credentials at `/oauth/token`. Hosts, paths and query documents are fixed in code; callers supply only a validated opaque 16-character report code, a fight ID and a player actor ID. It never accepts a user GraphQL document, bearer token or arbitrary URL. Redirects are disabled, each HTTP request has a ten-second ceiling, responses have a four-MiB ceiling, token acquisition is coalesced, and a 401 permits one token refresh. Errors contain safe codes rather than provider messages, response bodies or URLs.

Both metadata and every event page require an explicit public visibility value and the requested report code. Private, unlisted, missing and unspecified visibility never publish report data. GraphQL partial successes with errors are rejected. Known authorization denials take priority over usage-persistence failures so a budget outage cannot suppress the worker's privacy response.

The first event page also requests a bounded `CombatantInfo` selection for the selected fight and actor. The earliest valid event within the fight window supplies an optional stat snapshot. The normalizer accepts numeric fields at event level or under `stats`, keeps the values together as observed and omits unknown or conflicting fields. These values retain their source units and do not affect full-fight metrics. [Event types](https://www.warcraftlogs.com/v2-api-docs/warcraft/eventdatatype.doc.html) · [Combatant info event](https://www.warcraftlogs.com/scripting-api-docs/warcraft/interfaces/RpgLogs.CombatantInfoEvent.html)

Every fixed GraphQL query requests hourly points usage. A valid observation is supplied to the application's shared budget callback; exhaustion pauses until the provider's reset time. HTTP 429 respects Retry-After without reducing it to a shorter local cap. Missing usage stays unknown. Request count and points consumption are separate constraints.

Metadata is normalized deterministically, sorted by fight/actor ID, and limited to 200 fights and 1000 actors as application resource bounds. Missing collections remain null; explicit empty collections remain empty. A fight's explicit `friendlyPlayers` values become nullable `participant_ids`. A known nonparticipant cannot be analyzed merely because the player appears elsewhere in the report. If the participant list is unavailable, actor events can establish presence; a complete but empty actor stream cannot establish zero activity without confirmed membership.

Event pagination covers the fight window and includes incoming observations. The adapter requests up to five pages with a limit of 2000 per page and retains up to 10000 normalized events. A bounded overflow at the page's last timestamp is accepted. Missing or malformed pages, unsafe values, repeated or non-increasing cursors and truncation mark the collection incomplete. Unknown event kinds keep completeness unconfirmed. The adapter stores normalized observations.

When the fight-wide stream reaches its cap, the adapter can fetch a second bounded stream for the selected actor using `sourceID` and `dataType: All`. The same five-page and 10000-row caps apply independently. Only damage and heal events whose source ID equals the selected actor contribute. Each page must match the public report and the requested fight window. The second stream supplies full-window amount metrics only after its cursor is exhausted. The response marks that provenance with `actor_amount_events_complete: true`. The fight-wide stream remains incomplete, so cast, interrupt and death counts remain null.

`event-amounts/whole-fight-v1` sums normalized damage and heal event `amount` for the exact source actor and divides by the full fight duration in seconds. It uses direct actor events, excludes pets and reports the project's own rates. The normalized healing contract treats `amount` as effective healing. Overhealing is recorded separately and its percentage is `overheal / (effective healing + overheal) * 100`, unknown for a zero denominator. Deaths use the target actor. A confirmed empty complete window can produce zero. A metric without complete coverage or valid amounts remains null. Invalid or missing amounts are marked with `AMOUNTS_UNAVAILABLE`. Numeric sums and rates must remain finite and within JavaScript's safe numeric bound.

Ability rows contain only observed records and are interpreted with `events_complete`. The timeline is capped at 500 actor-related observations, retaining up to the latest ten deaths and twenty preceding observations from the ten seconds before each death, then filling with early events in chronological order. `timeline_truncated` explicitly marks omitted observations. No death is classified as a player error. Rotation rules, cooldown opportunity rules and buff-uptime interpretation remain Unknown without validated context and rules.

The separate combat fixture provider contains only `DEMOCombat000001`; all names, IDs, timestamps, events and totals are synthetic. Fight 1 demonstrates exact-actor damage and effective healing/overheal, incoming damage and a death; fight 2/player 1 demonstrates an incomplete stream, and fight 2/player 2 demonstrates a confirmed empty stream. It is never an automatic fallback for an external outage.

Tests use synthetic HTTP responses. They cover OAuth coalescing, one-time unauthorized recovery, privacy, partial GraphQL errors, safe errors, usage callbacks, Retry-After, pagination limits/cursors, identity precision, participant binding, SSRF/redirect/body limits, null/zero, rate overflow, attribution, incomplete observations and retained death evidence.

On 3 November 2026 a public Retail report verified OAuth, report metadata, pagination and the participant stat snapshot through the running API. The master actor list included a reserved Environment NPC with ID `-1`, which the adapter omits. For the sampled fight, the complete source-filtered response and the complete unfiltered reference returned the same 552 exact-actor damage and heal records. The damage-only filter returned fewer exact-actor records, so the adapter uses `dataType: All`.

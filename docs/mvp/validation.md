# Проверка проектных контрактов

30 октября 2026 года. Архив первичной проверки документов MVP v0.1 до реализации. На момент этого прогона приложения ещё не было. Текущие результаты находятся в [отчёте о реализации](../operations/implementation-validation.md).

## Выполнено

| Объект | Способ | Результат |
| --- | --- | --- |
| [OpenAPI](../../api/openapi/mvp-v1.yaml) | Swagger Parser 13.1.0: validate и разрешение ссылок | Валидный OpenAPI 3.1.0, 9 маршрутов |
| JSON Schema | Ajv 8.20.0, dialect 2020-12, ajv-formats 3.0.1 | Скомпилированы все 33 схемы; проверены все 14 вхождений inline-примеров запросов/ответов |

| [SQL-схема](schema.sql) | Выполнение целиком в пустом PGlite 0.5.13 / PostgreSQL 18.6 в памяти | Созданы 9 таблиц без расширений и внешнего сервера |
| Ограничения DDL | 14 проверок с синтетическими строками | Ожидаемые успешные операции и SQLSTATE для нарушений ограничений |
| Nullable talents в БД | Отдельный insert/read | Неподтверждённые active flag и nodes сохраняются как null |
| [Приёмочная матрица](acceptance-tests.md) | Подсчёт и просмотр сценариев | Подготовлено 56 сценариев; сценарии приложения ещё не исполнялись |
| Локальные ссылки Markdown | Проверка существования файлов | Цели ссылок существуют |
| [Исходная архитектура](../architecture/v1.0.md) | Сравнение с приложением пользователя | Сохранена без изменений |

14 проверок DDL покрывают разделение одинаковых имён по регионам, запрет realm другого региона, единственность активного задания, обязательные lease-поля running job, принадлежность current snapshot, единственность snapshot на job, предел возраста секции 720 часов, отсутствие payload у unavailable, отличие неизвестных зачарований от пустого списка, единственность активного loadout, согласованность маркера карантина и его сохранение, возможность нового задания после terminal state, каскадное удаление персонажа со связанными данными и сохранением другой идентичности.

Временные проверочные скрипты и npm-зависимости размещены в `%TEMP%\kipet-mvp-spec-check`, отдельно от проекта. В этом рабочем окружении повторный запуск:

```powershell
node "$env:TEMP\kipet-mvp-spec-check\validate.cjs"
node "$env:TEMP\kipet-mvp-spec-check\validate-extra.cjs"
```

## Границы результата

PGlite проверяет исполнимость DDL и ограничения на одном подключении. Не проверены конкуренция workers, row locks/SKIP LOCKED между соединениями, реальный Redis, миграции/откат, Go Race Detector, браузерный E2E, производительность и production deployment. Эти проверки входят в приёмку будущей реализации и требуют настоящего PostgreSQL/Redis.

Текущая live-схема Blizzard и актуальные игровые правила не подтверждены синтетическими примерами. Авторизация реального провайдера, сохранение реальных профилей и внешнее развёртывание не выполнялись. [Источники и границы проверки](sources.md) описывают, что необходимо сверить при подключении интеграций.

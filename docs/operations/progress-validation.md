# Этап 3: Mythic+ и рейдовый прогресс

1 ноября 2026 года. Локальная версия API 0.3.0. Проверка выполнена на синтетических данных; реальные Blizzard credentials не использовались.

## Реализация

Добавлены `GET …/mythic-plus` и `GET …/raids`, нормализованные DTO и две отдельные вкладки RU/EN. Профиль сообщает coverage шести секций. Прогресс загружается лениво, сверяет character/snapshot ID с показанным профилем, отменяет прежний запрос при смене контекста и скрывается при недоступности обязательного профиля. После фонового обновления другого снимка интерфейс предлагает перечитать профиль. Обрабатываются как 202, так и 200 unavailable с job ID при первом чтении старого снимка.

Mythic+ показывает наблюдаемый рейтинг, подтверждённый сезон, признак текущего сезона, лучшие записи и сезоны индекса. Охват задан `season_best`, `current_period_best` или `unknown`; полной истории ключей и Great Vault нет. Исторический выбор сезона пока не реализован. Текущий сезон не определяется по максимальному ID или календарю. Явный региональный каталог кешируется на час с объединением одновременных запросов. Рейтинг и прохождения текущего индекса не получают подпись сезона из старого каталога без подтверждённой связи; переход между сезонами покрыт регрессионными тестами.

Рейды показывают дополнения, рейды, сложности, наблюдаемый статус и боссов, включая исторические записи. Неизвестные счётчики и списки остаются null; подтверждённые нули и пустые списки сохраняются отдельно. Даты включают год. Приложение не угадывает актуальный рейд или оценку игрока.

Миграция 0006 расширяет `snapshot_sections` и добавляет старым снимкам unavailable/never_fetched без payload. Первая загрузка такой секции сразу ставится в очередь. Публикация сохраняет шесть секций одной транзакцией. Progress payload хранится в JSONB; отдельная накопительная таблица прохождений из проектного DDL не используется. TTL каждой новой секции — 15 минут, максимум хранения — 720 часов с обязательной пригодностью профиля. Старый прогресс не переносится в новый снимок при сбое, чтобы не смешивать сезоны. Кеш анализа и Rule Engine по-прежнему используют четыре исходные секции.

## Источник и ограничения

В fixture все ID, сезоны, подземелья, рейды и числа вымышлены. Два прохождения демонстрируют своевременное завершение и превышение времени. Рейды демонстрируют положительное число убийств, подтверждённый ноль и неизвестное. Режим явно указан в UI и `meta.source=fixture`. Raider.IO не подключён.

Адаптер Blizzard использует серверный OAuth и существующий общий бюджет запросов. Необязательные 404/ошибки секций не удаляют основной профиль; проверяются идентичность и соответствие выбранного сезона. Тестовые HTTP-ответы созданы для проверки контракта, а не получены из живого API. Официальные порталы Profile и Game Data на момент работы не дали извлечь полное описание схемы. Live-поля, доступность конечных точек и реальные ограничения требуют проверки с credentials и обезличенными ответами. Публичная эксплуатационная приёмка этим этапом не заявляется.
